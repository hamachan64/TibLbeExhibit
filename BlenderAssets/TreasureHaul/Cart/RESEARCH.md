# R.E.P.O. 参考調査と台車の改訂（2026-10-19）

前案は資料の裏付けがなく、細い柵・高い押し手の一般的な作業用台車へ寄りすぎていた。今回は参考資料の確認後、深い箱型荷室と計測器を持つ回収機械として改訂した。

## 調べた資料

1. [semiwork 公式 Steam 紹介](https://store.steampowered.com/app/3241660/REPO/)。失われた人類の残した環境から、壊れやすい物も含めて協力して搬出する設定を確認。
2. [公式ストアの画像一覧](https://store.steampowered.com/api/appdetails?appids=3241660)で公開されているスクリーンショット5枚を取得し目視確認。廃れた館・展示空間、くすんだ面、角張った造形、暗い環境中の明るい数値表示を確認。取得した画像は一時フォルダだけに置き、ゲーム素材には含めていない。
3. [GamerBlurb「R.E.P.O. Does Loot Respawn?」](https://gamerblurb.com/articles/repo-does-loot-respawn)の semiwork クレジット付きゲーム画像を目視確認。長方形の荷室、分厚い上縁、押す側の機械パネル、その下の大きな金額表示「$35,222」を確認した。記事本文のリスポーン説明を今回の仕様根拠にはしていない。

公式映像のリンクも確認したが、動画全編を視聴したとは扱っていない。静止画から分からない内部処理・正確な寸法・台車の物理仕様は推測で断定しない。

## 観察から制作へ

| 観察 / 前案との差 | 改訂で採用したこと |
| :--- | :--- |
| 浅い板の荷台より、物を中に収める長い箱の印象 | 深さ約0.31mの荷室、太い上縁、四隅の保護部材 |
| 道具が機械として見えるパネル構成 | 低い押し手、大型計測画面、窪んだ側面パネル・通気口 |
| 暗い面と明るい数字の対比 | 青黒い画面に黄緑系の数字。単位は既存仕様の G |
| 細部より角張った面と古びた材質 | 低ポリゴンの面取り、くすんだ緑灰色、自作の細かい塗装欠け |
| 前案の露出した車輪が普通の台車に見えた | 駆動部の外装で車輪を一部覆い、重い機械の下部に変更 |

ロゴ、固有の操作アイコン、形状の正確なトレース、画像・音・モデルの流用はしていない。古代遺跡の発掘隊が使うオリジナルの回収装置とする。全空間を暗くする映像効果は、パススルーMRの会場視認性と異なるため採用しない。

## 金額表示の仕様

ユーザー指定により「台車内の現在価値の合計」を表示。参照画像は数値表示の存在を示す資料であり、以下の集計の詳細は本プロジェクト用に決めたもの。

- 空荷は `0 G`、例は `3,600 G`。数字はモデルに焼き込まず、Unity の TMP で更新する。
- `CargoValuable` の積載判定点が台車内にある、持たれていない、有効なお宝だけを合算する。
- 取り出し、持ち上げ、無効化・破壊、現在価値の減額を反映する。約0.1秒周期で更新。
- 複数 Collider の同一お宝を二重計上しない。Collider の Enter/Exit 回数に依存しない。
- 累計回収スコアは別の値。ここから加算・回収通知を発火しない。未実装のホスト状態管理との接続には `SetCurrentValue` / `SetHeld` / `SetEligible` を使う。
- 本編のホスト同期・移動式台車の操作は未実装。今回の統合対象はPrefabと独立した確認シーン。

## 会場と性能

外寸 0.816 × 1.204 × 0.780m、4,432三角形、9メッシュ。表示は追加のTMPメッシュ1個。最狭1.26mの通路の左右余裕は各0.222m、台車中心の保守的な旋回直径は1.484m。狭い区間でのその場旋回・人とのすれ違いは想定できない。実物台車への位置合わせ・PICO実機性能は別途確認する。
