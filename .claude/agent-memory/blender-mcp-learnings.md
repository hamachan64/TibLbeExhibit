# Blender MCP 学習メモ

Blender MCP（`mcp__blender__execute_blender_code`）でモデリング作業をした際のハマりどころ。
環境: Blender 5.1.2 / 日本語UI / ポート9875。

## 1. Principled BSDF ノードは名前で取得しない
- 日本語UIでは `nodes.get('Principled BSDF')` が `None` を返すことがある。
- **回避策**: `for n in mat.node_tree.nodes: if n.type == 'BSDF_PRINCIPLED'` でタイプ検索する。
- Principledの入力名はバージョン差があるため `"Transmission Weight"` / `"Transmission"` の両対応で `in bsdf.inputs` チェックしてから設定する。

## 2. `object.copy()` + `collection.objects.link()` で作った複製が描画されない
- Blender 5.1 + MCP経由の実行で、`obj.copy()`（メッシュ共有）で量産→ `bpy.context.collection.objects.link()` したオブジェクトが、
  `visible_get()==True`・位置/メッシュ/コレクション所属もすべて正常なのに、**ビューポートにもレンダーにも一切描画されない**現象が発生した。
  `view_layer.update()` や depsgraph 評価でも解消しなかった。
- **回避策**: `bpy.ops.mesh.primitive_*_add()` で個別に生成し、必要なら `bpy.ops.object.join()` で1メッシュに統合する（チェーン52リンクで実績あり）。

## 3. 同一スクリプト内での「生成→即レンダー」は避ける
- オブジェクト生成とF12レンダー（`bpy.ops.render.render(write_still=True)`）は別のexecute呼び出しに分けたほうが安全。

## 4. チェーン（鎖）のモデリング
- Arrayモディファイア（オブジェクトオフセット+FIT_CURVE）+ Curveモディファイアの定番構成は、MCP経由だとリンクが散乱して安定しなかった。
- **回避策**: 円周上にパラメトリック配置（接線方向に回転 + 交互に±50°ロール）が確実で、ケーブルチェーンらしく見える。

## 5. 既存オブジェクトの移動でもモディファイア評価が固まる
- Shrinkwrap等のモディファイア付きオブジェクトを `obj.location` で移動しても、MCP経由だと再評価されず、
  レンダーに未変形（または旧形状）のまま出ることがある。
- **回避策**: 位置を変えたい場合はオブジェクトを削除して新しい位置で `bpy.ops` から作り直す。

## 6. Unity向けFBXエクスポートの実績レシピ（Blender 5.1）
```python
bpy.ops.export_scene.fbx(
    filepath=..., use_selection=True, object_types={'EMPTY','MESH'},
    use_mesh_modifiers=True,   # Shrinkwrap/Solidify/Booleanを焼き込み
    mesh_smooth_type='OFF', global_scale=0.03,
    apply_scale_options='FBX_SCALE_ALL',
    axis_forward='-Z', axis_up='Y', bake_space_transform=True)
```
- 空のルート（例: PaladinNecklace）に全パーツを親子付けし、ルートから再帰選択して `use_selection=True` で書き出す。
- ブーリアンのカッターは親子付けしない＋`hide_render=True` にしておけば選択から自然に外れる。
- 書き出し先は `Assets/_Content/Models/`。書き出し後は必ず uloop 経由で `AssetDatabase.Refresh()` → .meta生成を確認（unity_asset_rules準拠）。

## 7. その他
- ビューポート確認は `space.shading.type='MATERIAL'` + `region_3d.view_perspective='CAMERA'` + `overlay.show_overlays=False` にしてから `get_viewport_screenshot`。
- 成果物の .blend は Unity の `Assets/` 外（`BlenderAssets/`）に保存する（.meta汚染防止）。

## 8. CardBinder（ページめくり可能な本）制作での追加学習（2026-07）
- **大量サブパーツは bmesh で1メッシュに直接構築**: `bmesh.ops.create_cube(bm, size=1)` で返る verts を手動スケール/移動し、面の `material_index` を直接設定する方式なら、#2 の copy() 描画バグを完全回避できる（1ページ=箱73個でも一発成功、8ページ分ループ生成OK）。
- **可動パーツのピボット設定**: 3Dカーソル移動 → `bpy.ops.object.origin_set(type='ORIGIN_CURSOR')`。ページめくり用は「各オブジェクトの原点を背表紙軸上（自分の平面高さ）」に置き、Unity側は localRotation 回転のみでめくれる。
- **実寸（メートル）モデリングなら `global_scale=1.0`** + `apply_scale_options='FBX_SCALE_ALL'` でUnityに1:1で入る（Unity側 globalScale=1 / fileScale=1 を確認済み）。#6 の 0.03 はモデルを拡大して作った場合の値。
- **bake_space_transform の座標系変換で、Unity上では子のローカルX座標の符号が反転する**（Blender -0.022 → Unity +0.022）。バグではなく右手系→左手系変換の仕様。
- **カメラの向きは手動Eulerでなく** `(target - cam.location).to_track_quat('-Z','Y').to_euler()` で確実に狙う。
- ビューポートはユーザー操作等でカメラビューから外れることがある。スクリーンショット直前に毎回 `view_perspective='CAMERA'` を設定し直すのが安全。
- **平面に置くフラットな三角/菱形は `primitive_cone_add(vertices=3or4, depth=極小)` をそのまま使う**（三角形の面は最初からXY平面にある）。X90°回転＋スケールで倒そうとすると極薄の縦板になり見えなくなる。向きはZ回転だけで調整し、裏面（-Z側）に見せる場合はX180°回転を使う。
- FBXを**同一パスに上書きエクスポートすればUnityのGUIDは維持される**（プレハブ等の参照が切れない）。モデル修正時は削除→再作成ではなく上書きすること。
- **Unityプロジェクト内（Assets/配下）の画像をBlenderのImage Textureノードに読み込んでFBXエクスポート（path_mode='AUTO'）すると、Unity側で自動的にそのテクスチャがマテリアルの_BaseMapにリンクされる**（URP Lit・ImportViaMaterialDescription経由、リマップ作業不要）。
- 本の表裏スプレッドテクスチャのUVは、ワールドX座標→U の線形写像1本で裏表紙・背・表紙の3オブジェクトに共通適用できる（実寸比とテクスチャ領域比を合わせておくのが前提）。bmeshの `loops.layers.uv.new()` で面ごとに手動UV設定。
- 開いた本を真下から見るビュー（視線≈+Z）は `to_track_quat('-Z','Y')` のロールが縮退して180°回転して見えることがある。**鏡像と回転を混同しない**こと（回転なら正しい）。
- **リングバインダーの綴じ機構は「リング軸＝背表紙の中心線(x=0)＝全ページのピボット」の3つを一致させる**。2段階で指摘を受けた: ①ページのピボットが背表紙中心のままだと綴じ穴が回転中にリングから外れて突き抜ける、②リングを裏表紙のヒンジ位置に置くと綴じ側が右に偏って見える。正解は `Rings中心 = Pages pivot = (0, 0, ページ束の中心z)`。ページは綴じ代を背表紙中心より外側まで伸ばし、リング位置にY方向の切り欠きを作る。全ページが同一軸で回るのが実物の挙動どおりで、めくった順の積層も正しくなる。
- 9ポケットリフィルは**スロット63×88mm（トレカ実寸）×3×3＋綴じ代**で組むとページが約221×290mm（A4相当）に収まり、実物と同じプロポーションになる。寸法を実物基準で決めると各部のマージンが自然に決まる。
- **同じ模様が大量に反復する部位（ポケットの押さえリブ等）はジオメトリでなくテクスチャにする**。ページ8枚×両面×9ポケット×4本のリブを箱で作ると10,612tris、1枚のBaseMap（512px）に置き換えると3,700trisで**見た目はほぼ同一**（失われるのは側面の陰影のみ）。UVは対象のクアッドだけ0-1に手動割り当てし、単色マテリアルの面は `(0.5,0.5)` に潰せばSmart UV Project不要。
- **UV付きクアッドを裏面用に反転するときは頂点列とUV列を両方 `reverse()`** する。片方だけだと頂点とUVの対応がずれて模様が回転する。
- テクスチャ内の模様は**UV0-1が実寸何mmに対応するかで px を逆算**する（縦横比が1:1でない面では、横方向と縦方向で別々に換算しないと線の太さが歪む）。2倍解像度で描いて `reshape(S,2,S,2,4).mean(axis=(1,3))` で縮小するとアンチエイリアスされる。
- **実物写真リファレンスで「一部しか写っていない部品」の全体形状を推測で埋めない**。裏表紙内側のデバイスパネルを、ページに隠れて右端だけ見えていた状態から「幅45mmの細帯」と誤解し、実際は裏表紙内面ほぼ全面（液晶＋スピーカー＋ボタン群）だった。**別アングルの資料を要求するか、見えていない範囲は明示して確認する**こと。
- **リファレンスにない要素を「それらしいから」で足さない**（表紙内側に白い見返しを創作して指摘された）。原作モノは資料にある要素だけで構成する。
- **黒い部材がレンダーでグレーに浮くのは Specular（IOR Level）が原因**。BaseColorを下げても直らない。`Specular IOR Level ≈ 0.2` ＋ roughness 0.6前後で締まる（液晶画面・カードスロット等）。
- `primitive_cylinder_add(vertices=3)` の三角形は**初期頂点が +90°（+Y）方向**。向き角 a に向けるには `zrot = a - 90°`。円周配置と同じ角を回転にも使うと風車状にずれる。

## 9.5 Blender MCPは複数タスク間で共有される（2026-07）
- Blender MCP（ポート9875）は単一のBlenderプロセスに接続する共有インスタンス。並行して他のモデリングタスクが動いていると、**作業開始時に指示された`.blend`ファイルが開かれているとは限らない**（例: 「一坪の密林」担当タスク開始時、実際には別タスクの`CardItem_BubbleHorse.blend`が開いた状態だった）。
- **回避策**: 作業前に必ず `bpy.data.filepath` と `bpy.data.objects` 一覧で現在開かれているファイルを確認する。想定と違う場合は `bpy.data.is_dirty` / `bpy.data.is_saved` で他タスクの未保存変更が無いことを確認してから `bpy.ops.wm.open_mainfile(filepath=...)` で目的のファイルに切り替える（未保存の変更があれば安易に切り替えず報告する）。
- 対象の`.blend`が既にディスク上に保存済み（他プロセスがモデリングを完了させて保存済みだが、その後Blender上では別ファイルに切り替わっていた）というケースだったため、ディスク上の最新版を開き直せば作業に支障はなかった。

## 9. 千里眼の蛇（チューブ状生物モデリング）での追加学習（2026-07）
- **`get_viewport_screenshot` が突然真っ黒を返し続けることがある**（tag_redraw等でも回復せず。ウィンドウのオクルージョンが原因の可能性）。確実なのは EEVEE で `bpy.ops.render.render(write_still=True)` によるファイル出力→Readで確認する方法。または `view3d.view_selected` オペレータでフレーミングすると回復した実績あり（`region_3d.view_location`/`view_distance` の手書きは信頼できない）。
- **パス沿いチューブ（蛇・ロープ等）の鉄則: パスの曲率半径 > 断面半径**。違反すると曲がりの内側でリングが交差し「ヒダ／フラップ」状の破綻ジオメトリが出る（顎の下に謎の三角フラップとして現れた）。sin/cosイージングは曲がりが終端に集中して局所曲率が急になりがち。**首のような90°ターンはCatmull-Rom制御点で明示的に設計**し、`連続リング間の角度変化から最小曲率半径を数値チェック`してから確定する。
- **チューブUVのアスペクト補正**: U=周方向・V=弧長比のUVでは、世界空間のスケールが U:周長(〜0.17m) vs V:全長(〜1.2m) と大きく異なる。テクスチャに丸い模様を描くには `rv = ru × (周長/全長)` の補正が必須（忘れると模様が体軸方向に細長く伸びる）。
- **半埋め込みの目玉等は「中心がメッシュ内部にあるのが正常」**。サブエージェントやレビューアが「メッシュ内部にある＝バグ」と誤判定して動かすことがある。指示時に意図を明記するか、結果を必ず自分でレンダリング確認する。
- `mathutils.bvhtree.BVHTree.find_nearest()` の返す法線は**メッシュによっては外向きと逆**のことがある。法線方向オフセットの前に、レイキャストのパリティ判定（内外判定）で±両方向を検証すること。
- uloop-execute-dynamic-code 内の `DestroyImmediate` は `using System;` と衝突して CS0104 になる → `UnityEngine.Object.DestroyImmediate(...)` と完全修飾する。
- パラメトリック生成の中間データ（パス点・フレーム軸・断面プロファイル）は `bpy.app.driver_namespace` に入れると同一Blenderセッション内の後続execute呼び出しから参照できる（目・舌の配置に使用）。
- **【最重要】bmesh手組みメッシュの法線内向き → Unityで「透過」**: bmeshで面を張ると、ワインディング次第で法線が内向きになることがある。Blenderのビューポートは両面表示なので**一見正常に見える**が、UnityのURP Lit（Opaque）は裏面カリングするため、体の向こう側＝背景が透けて見える（ユーザー報告「透過されて見える」＝マテリアルやアルファではなく法線が犯人）。**エクスポート前に必ず符号付き体積 `Σ dot(face.center, face.normal)*face.area` の符号で外向き（正）を検証**し、負なら `bmesh` で全面 `f.normal_flip()` する。閉じたメッシュ（胴体・舌）が対象。目のような凸球は `create_uvsphere` なので元から正しい。

## 10. バブルホース（四足獣・ヘッドレスCLIパイプライン）での追加学習（2026-07）
- **MCP不要のヘッドレス実行が安定**: `blender.exe --background --python script.py` で「因子設定リセット→構築→保存→レンダー」まで1スクリプトで完結できる。MCPの共有インスタンス問題（§9.5）も回避できる。イテレーションはスクリプト修正→再実行が確実。
- **Blender 5.1のEEVEEエンジン名は `'BLENDER_EEVEE'`**（4.xの `'BLENDER_EEVEE_NEXT'` はenumに存在しない）。try/exceptで両対応にするか5.1名を使う。
- **四足獣はSkinモディファイア骨格が高速**: 背骨＋首＋頭チェーンに脚を分岐させ、`mesh.skin_vertices[0].data[i].radius=(ry,rz)` で肉付け→Subsurf2。ただし**分岐部の内部にジャンクフェイスが残る**（下記AO問題の原因）。
- **【重要】AOベイクは内部ジャンクフェイスで破綻する**: Smart UV Projectは折り重なった島や内部フェイスを可視フェイスと同じテクセルに重ねることがある。位置ベイク（EMIT）は内部フェイスでも座標がほぼ同じため実害なしだが、**AOベイクはAO=0の黒がハードエッジのパッチとして可視面に混入**する（体表に暗い多角形の「シミ」）。対策: AOベイクをやめ、**ベイクした位置から numpy でプロシージャルシェーディング**（腹下・脚内側・付け根リング等をsmoothstepで暗く）を合成するのが決定論的で安定。
- **レイキャストパリティで法線修正は危険**: 表面すれすれのレイのグレージングヒットで正常フェイスまで大量誤反転する（444面反転して大破損）。法線検証は「バックフェイスカリングONでレンダーして穴を見る」のが確実な診断方法。`normals_make_consistent` が通っていれば可視面はまず正しい。
- **位置ベイク→numpyペイントのテクスチャ生成が強力**: Geometry.Position+2.0（負値対策）をEmissionでベイク→ピクセルごとに設計空間座標で領域マスク（ポリライン距離＋三角波でジグザグ模様等）を評価して1枚のBaseMapを合成。テクセル解像度で模様のエッジが出るので頂点カラーより高品位。**未ベイクテクセル（折り島の穴）は近傍拡散でインペイント**する（`|pos_raw|≈0` で検出、4近傍平均を反復）。
- スケール定数や重心オフセットは `obj["design_offset_x"]` などカスタムプロパティに保存すると、後段のテクスチャスクリプトから安全に参照できる。

## 11. キングホワイトオオクワガタ（可動パーツ分割・刃状プレート）での追加学習（2026-07）
- **アニメ系リファレンスの平たい刃形状は「輪郭ポリゴン押し出し」が有効**: クワガタの大顎のような形は、チューブ+突起の組み合わせより「上面視の輪郭点列（14〜20点）を定義→押し出し」が再現しやすく、ユーザー指摘への修正も輪郭点の編集だけで済む。
- **肉厚な刃**: 単純押し出しは「厚紙の切り抜き」感が出る。断面プロファイル `[(内オフセット, z比率), ...]`（底0.002内→外→中央-0.0012外膨らみ→外→天面0.002内→キャップ0.005内/z1.22）でドーム状の肉厚断面になる。内側オフセットはマイター法線によるポリゴンオフセット（面積符号で内外判定・cosクランプ0.35）で凹輪郭でも破綻しない。キャップ三角化は `mathutils.geometry.tessellate_polygon`。**細いプロング幅の半分を超えるキャップ内オフセットはエッジを鈍らせる**（0.0085→0.005で解決）。
- **可動パーツ分割ワークフロー（リジッド分割）**: グループごとに独立bmesh→法線検証→**ワールド座標のままUV割り当て→`bmesh.ops.translate`で-pivot移動**→`obj.location=pivot`→ルートEmptyへ親子付け。実績FBXレシピ（global_scale=1.0 / FBX_SCALE_ALL / -Z,Y / bake_space_transform）で階層・ピボットがUnityに1:1で保持され、Unity側はlocalRotationを回すだけで大顎開閉・脚可動ができる（SkinnedMesh不要でMR向き）。
- **半埋め込みパーツはボディ形状変更で埋没する**: 頭部を拡幅したら複眼が完全に内部へ埋まり「目がない」指摘を受けた。ボディ側パラメータ変更のたびに露出量を再確認すること。
- EEVEEの3点ライトはメタリック白系マテリアルだと容易に白飛びし、テクスチャの陰影・銀色感が伝わらない。**検収レンダーは露出-0.5前後＋ライト弱め**にする（テクスチャ自体はPNGを直接Readして確認するのが確実）。
- サブエージェント（Sonnet）へのUnity取り込み・プレハブ化依頼は「前例コミットを `git show <hash> --stat` で調査→同一パターンで作成」と指示すると、プレハブ構成・SO登録まで正確に踏襲される。制約（YAML直編集禁止・C#変更禁止・DestroyImmediate完全修飾）を明示すること。

## 12. リモコンラット（球面UVアトラス・複合キャラ＋鎧）での追加学習（2026-07）
- **`bm.to_mesh()` は bmesh の頂点生成順を保存しない**。「最初のN頂点=球、以降=追加コーン」のようなインデックス範囲での部位判別は誤爆する（混在面48個が発生）。**union-findの連結成分分解で判別する**のが確実。
- **球面/円筒UVをアトラスの部分領域に入れると、シーム跨ぎ面が隣の領域をサンプリングして汚染する**（背中に茶色い縦縞が出た）。対策は2通り: (a) ラップする部位はU方向全幅[0,1]を占有させ、他パーツはVバンドに退避（textureのextension=REPEATで連続）。(b) 左右対称パーツ（鎧の胴・兜）は**折り返しUV `|atan2(x,-y)|/π`**（正面0→背面1、左右ミラー共有）にするとシーム自体が消え、テクセル密度も2倍になる。
- **AgXビュー変換はパステルカラーを大きく脱色する**。テクスチャ色の検収レンダーは `view_settings.view_transform='Standard'` にする（その際ライトは強すぎになりがち。エリアライト0.6m/距離0.5mならKey≈13W・Fill≈4W目安。Standardへ切替時は要再調整）。
- **Blender再起動で `bpy.app.driver_namespace` が消える**（MCP共有インスタンスの宿命）。ピボット/親子のメタデータはチャット側に控えておき、インライン再定義で復旧できるようにする。再接続時は §9.5 どおり filepath とオブジェクト一覧をまず確認（今回：鎧パーツは直前の保存で無事だった）。
- **ネスト階層のピボット設定（鎧の腕・脚チェーン）**: 親→子の順に `verts -= own_pivot` → `obj.location = own_pivot - parent_pivot` → `obj.parent = parent`。FBXでUnityに1:1で入り、localRotationだけで関節が曲がる。
- 関節球（肘・膝）とチューブが浅い角度で交差すると**鋸歯状のシルエット**が出る。スタイライズド装飾に見えるので許容可だが、嫌なら球を8%大きくして交差を深くする。
- 顔テクスチャの「困り眉」は向きに注意: **八の字（内側が高く外側へ垂れる）**でないと怒り顔になる。アークより2セグメント折れ線が制御しやすい。

## 13. リモコンラット後半（毛ジオメトリ・鎧作り込み・Poly Haven）での追加学習（2026-07）
- **Poly Haven連携が無効でも `bpy.context.scene.blendermcp_use_polyhaven = True` をexecuteで設定すれば有効化できる**（アドオンUI操作不要）。ダウンロードしたテクスチャは `bpy.data.images` に `<id>_diff_1k` 等の名前で入るのでnumpyで直接合成に使える。
- **ウェザリング合成は「錆マスクの閾値」が命**: rust系テクスチャは全面が錆色なので、低い閾値で合成すると鎧全体が茶色化して鋼感が死ぬ。`smoothstep(0.62,0.85, 錆らしさ)` 程度で斑点状に絞り、**刃・鍔・グリップ・盾の赤などの特殊パッチはUV矩形でマスク除外**する。「錆らしさ」は `(R-B)*2.2 + (0.45-輝度)*0.8` で抽出できる。
- **「毛感」はテクスチャだけでは不十分と指摘されがち**。①縦方向に伸ばした異方性ノイズ（縦ブラー→横微ブラー）をBaseMapに、②ボディ頂点への正弦合成ノイズ変位（振幅=半径の2〜3%、顔部は1/3に減衰）、③シルエット部への小コーン毛束（r0.0024・len6〜8mm・下向き30-55°）、④頭髪は8本のコーンクランプ、の4点セットで立体的な毛感になる。スパイクのUVは**基部のボディUV1点に潰す**と色が馴染む。
- **「エッジを効かせる」= EdgeSplitモディファイア(38°) + 角のあるジオメトリ**。球や滑らかロフトのままではチープに見える。肩甲は「球の緯度帯を円錐フラスタム帯3枚（厚み付き）」に、サバトンは断面列の角柱ウェッジにすると板金らしくなる。EdgeSplitはFBXエクスポート時に `use_mesh_modifiers=True` で焼き込まれる。
- キャラの等身/形状の指摘（卵型→カプセル等）は**プロファイル関数を差し替えられるパラメトリック構築**にしておくと1チャンクで対応できる。capsule: 下キャップ+円筒+上キャップの区分関数。
- 全体スケール変更（0.7倍等）は「親Emptyのscale」でなく**メッシュ頂点とピボットlocationを両方0.7倍**してベイクする（Unity側のtransformを汚さない）。
- **単一点UV（バックル等の小物を1テクセルに潰す手法）は、同じパッチ内の帯UVレンジと重なりやすい**。塗り分けが必要な小物はパッチ外の空き領域に専用の小矩形を割り当てる（帯の折り返しUVはlu=1側=背面が端まで到達することを忘れない）。
- 「ファサッと感」のある毛束は太いコーンでなく**2セグメントの薄い短冊ブレード（両面貼り・先細り・ランダムに垂らす）**が正解。コーンは角に見えると指摘される。
- 毛皮マントにEdgeSplitを付けると結晶質の岩に見える。**布・毛皮などソフト系パーツはEdgeSplit除外**。

## 15. 奇運アレキサンドライト（宝飾指輪・マルチマテリアル）での追加学習（2026-07-20）
- **【工程教訓】低解像度カード画像からの意匠推測は検収前に依頼者へ確認する**: 初版は「花弁状ベゼル+青緑宝石+薔薇」で作ったが、高解像度カード+アニメスクショの提示で「ひし形土台+上下渦巻きスクロール+左右サッシュ+赤系宝石」に全面作り直しになった。パラメトリック構築（bmesh再実行）だったため作り直しは約30分で完了——**手作業スカルプトでなくスクリプト構築にしておくことが再設計保険になる**。原作モノは着手前に必ず一次資料（原作/アニメの実物描写）の解像度を確認すること。
- 平面渦巻き（唐草スクロール）チューブは「リード直線3点+対数減衰螺旋20点」のパス+6角プロファイルで1本≈300tris。平面パスなら法線=(tan.y,-tan.x,0)/Z固定でねじれ無し。左右対称は sweep方向 s=±1 のミラーで作る。
- **【重要】bmesh opsを跨いだBMFace参照は黙って無効化される**: `bridge()`等で作った面のPython参照をリストに取っておき、後続の `bmesh.ops.create_uvsphere` 等を多数実行した後で `f.material_index=1` を設定すると、**例外なしで書き込みが消失**する（to_mesh後に該当インデックスの面が0個）。対策: 材質分けが必要なパーツは**金/エナメル等マテリアルごとに別bmesh→別オブジェクト化（各meshにマテリアル追加）→`bpy.ops.object.join()`** で統合すると、マテリアルスロットとmaterial_indexが自動リマップされ確実。
- **ファセットカット宝石は「楕円リング列＋bridge＋fan」+フラットシェーディング**が最速（16セグでクラウン2段+テーブル+パビリオン=160tris）。クラウンは低く（高さ≈長径の15%）テーブル広め（56%）にしないと円錐に見える。
- **アレキサンドライトの変色表現**: BaseColorテクスチャは深い青緑基調（角度マップで短軸端のみ赤紫）、シェーダ側は LayerWeight(Facing)→**Power(3.5)**→Mix(青緑テクスチャ, マゼンタ) が有効。Powerを挟まないと傾いたファセットが全部ピンクになる。白熱灯シーンではEmissionを赤紫(0.45,0.03,0.22)×0.35に切替えると変色デモになる（Unity側はシェーダパラメータ駆動を想定）。
- 宝石テーブル面の白飛びはエリアライトの映り込みが原因。Rimライトを小さく(size0.10)弱く(≈28W)、Specular(IOR Level)を0.3に落とすと収まる。
- 開いたシェル（リム天面等）は `recalc_face_normals` が不定 → 「天面は normal.z>0」等の明示チェックで反転修正。仕上げに全マテリアル `use_backface_culling=True` で表裏2アングルをレンダーし、欠け無し＝Unityセーフを確認する手順が手軽。

# 14. ステージプロップ一括制作（侵蝕する街アントキバ / 2026-07-19）での追加学習
