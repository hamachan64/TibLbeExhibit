# 権利・費用・セキュリティの確認ルール

外部の物を使う前に、次の4点を**毎回**確認する。1つでも確認できなければ使わず、ユーザーに報告して判断を仰ぐ。

## 対象
- 3D モデル・テクスチャ・音・音楽・フォント・画像（Asset Store、Web、Blender MCP の取り込み機能を含む）
- Unity パッケージ・ライブラリ・ツール（`Packages/manifest.json`、`Assets/Plugins/`、npm 等）
- 外部サービス・API・MCP（生成 AI、音声合成、3D 生成、クラウド）
- AI に作らせた成果物（生成に使ったサービスの規約に従う）

## 確認する4点

### 1. 商用利用できるか
- Inter BEE の企業ブースでの展示は**商用利用**として扱う。
- 「非商用のみ」「個人のみ」「要問い合わせ」「無料プランは商用不可」は使わない（例: ElevenLabs の無料プランは商用不可）。

### 2. 権利に問題がないか
- ライセンスは**公式ページの原文**で確かめる。ブログ・まとめなどの二次情報だけで判断しない。
- クレジット表記・改変・再配布・AI 生成である旨の表示の条件を控える。
- 実在のブランド・キャラクター・人物の声や顔、R.E.P.O の素材（名前・見た目・音）は使わない（企画書 1章: 参考にするのは遊びの仕組みだけ）。

### 3. 無料か（有料サービスにアクセスしないか）
- 有料プラン、従量課金の API、クレジット消費型の生成サービスにはアクセスしない。
- 無料枠・無料トライアルでも、商用不可のもの、使い切ると課金に切り替わるもの、カード登録が要るものは使わない。
- 月額サブスクに含まれると思っても、API は別課金のことが多い（例: ChatGPT の月額プランと OpenAI API は別）。確かめてから使う。
- 費用がかかる、またはかかるか不明なら、使う前にユーザーに確認する。

### 4. セキュリティに問題がないか
- 入手元は公式（開発元のサイト、Asset Store、パッケージの公式リポジトリ）に限る。
- ダウンロードした物は、スクラッチパッドの空のフォルダに置いて中身を確認してからプロジェクトに入れる。実行ファイル・エディタ拡張・スクリプト（`.cs` / `.dll` / `.py` 等）を含む素材は、中身を読んでから入れる。
- API キー・トークン・パスワードをリポジトリのファイルに書かない、コマンドやログに出さない。
- ネットワークから取ったスクリプトを直接実行しない。

## 記録
- 使うと決めた物は `THIRD_PARTY_NOTICES.md` に1行ずつ記録する（名前、入手元 URL、ライセンス、商用利用、費用、表示の要否、確認日）。
- クレジット表記や AI 生成である旨の表示が必要な物は、待機画面のクレジット欄に出す（要件定義書 N-9）。

## 機械的な歯止め（`.claude/hooks/guard.py`）
- 従量課金 API のドメイン（OpenAI・ElevenLabs・3D 生成サービス等）へのアクセスは、ユーザーの確認を求める。
- Blender MCP の有料・クレジット消費の生成機能（Hyper3D Rodin、Hunyuan3D）と、Sketchfab からの取り込みは、ユーザーの確認を求める。
- API キーらしき文字列をファイルに書き込もうとしたらブロックする。
- これらに止められたら迂回しない。何をなぜ使いたいかと、4点の確認結果を報告して判断を仰ぐ。

## dev-loop での扱い
- Phase 0: 外部の物を使うタスクは、仕様書の「外部の素材・サービス」欄に4点の確認結果を書く。
- Phase 3: レビューで、`Packages/manifest.json` の変更・`Assets/` への外部ファイルの追加・外部 URL へのアクセスを洗い出し、`THIRD_PARTY_NOTICES.md` と突き合わせる。
