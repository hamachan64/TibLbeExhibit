# 遺跡の亡霊（徘徊して、見つけたら罰を与える敵）

> 企画書 5.6 C の「遺跡のゴーレム」を、**亡霊**に置き換えて作る（2026-11-07 のすり合わせ）。
> 罰は2通りを作り、運営PCで切り替えて試す。展示でどちらにするかはデモ会で決める。

## 目的
本編中、中央の部屋の塊の周りを亡霊が1体ゆっくり巡回し、その視界に入った体験者に罰を与える。
「通路の角の先にいるかもしれない」「光の中に入らないように回り道する」という緊張感を、運搬に足す。

### ゴーレムではなく亡霊にする理由
- 体験者の体は仮想の敵をすり抜ける。石のゴーレムをすり抜けると嘘っぽいが、亡霊なら自然。
- 宙に浮いて滑るように動くので、歩く動きのアニメーションが要らない（仮の形でも成立する）。
- 「見つかる」という罰の理屈に合う（見張りの霊）。遺跡の発掘隊という設定にも合う。
- 怖くしすぎない（展示は一般客）。見た目は半透明で、目が光る程度にする。

## 決まったこと（すり合わせ）
| 項目 | 決定 |
| :--- | :--- |
| 今回作るもの | 亡霊だけ（石像は次のループ以降） |
| 数・巡回 | 1体。中央の部屋の塊の周りを一周し続ける（入口側の前 → 西通路 → 奥の横通路 → 東通路 → 入口側の前）。部屋と大広間には入らない |
| 見つかる条件 | 亡霊の前方の視界（扇形・壁でさえぎる）に、体験者の**頭**が入り続けたら |
| 罰 A「お宝を奪う」 | 見つかった人が持っているお宝（Held・Flying。両手なら両方）を亡霊が奪う。お宝は亡霊の方へ吸い込まれて消え、0G になる。何も持っていなければ罰なし |
| 罰 B「退場」 | 見つかった人は、その回はゲームオーバー（つかめなくなる）。持っていたお宝はその場でそっと置かれ（減額なし）、仲間が運べる。全員が退場したら、その時点で結果へ進む |
| 切り替え | 運営PCで「亡霊: なし ／ お宝を奪う ／ 退場」を待機中に切り替える |
| 見た目 | 仮の形（半透明のカプセルの体＋光る目＋床の視界の扇）。モデルは別のループで差し替える |
| 石像（参考・今回は作らない） | U-18 は「持っているお宝が即壊れる」、視界は「壁より背の高い石像が全体を見下ろす」に決定。企画書・TODO に記録だけする |

## 受け入れ基準
- [ ] 設定が「なし」のとき、亡霊は出ず、これまでと挙動が変わらない（既存の EditMode テストがすべて通る）
- [ ] 設定が「なし」以外のとき、Playing に入ると亡霊が現れ、Playing の経過時間から全端末で同じ位置・向きに決まる（位置の同期メッセージは足さない）。Waiting・Opening・Tutorial・Result では出ない
- [ ] 亡霊は経路を〔亡霊の速さ〕0.4 m/s で一周し続け、曲がり角では次の区間の方向へ向きを変える。経路の点は VenueRoot ローカル座標で、通路の中央（幅 1.2m の中心）を通る
- [ ] 体験者の頭が、亡霊の目から〔視界の距離〕3.0m 以内・正面から〔視界の半角〕35° 以内にあり、目から頭への線が高い壁（ビームを止める壁と同じ判定）にさえぎられないとき、「見られている」になる。水平の距離と角度で判定する
- [ ] 見られている状態が〔見つかるまでの時間〕0.7秒続くと「見つかった」になる。途中で視界を出ると数え直す。見られている間は、その体験者の画面で亡霊の目と床の扇が赤くなり、警告音が鳴る（使える音が無ければ音なしで、ログに出す）
- [ ] 見つかった判定は、その体験者の端末が自分の頭で行い、ホストへ送る。ホストは「Playing 中・参加端末・見学/退場でない・設定が なし 以外・同じ端末の〔見つかった後の無視時間〕3秒以内でない」を満たすときだけ罰を適用する
- [ ] 罰 A: ホストは、その端末が持っている本編のお宝（Held・Flying）をすべて消滅させ（現在の価値 0、状態 Destroyed、世代 +1）、全員へ知らせる。全端末で、お宝が亡霊の方へ吸い込まれて消える（砕ける演出ではない）。取りこぼしても `ThItems` で追いつく。失った額を回の記録に含める。何も持っていない端末の報告は、罰なしで捨てる
- [ ] 罰 B: ホストは、その端末をその回だけ「退場」にし、持っている・予約しているお宝をそっと置かせる（既存の見学への切り替えと同じ解放。減額なし）。退場した端末のつかむ申請は捨てる。退場の一覧は `ThState` にも載せ、取りこぼしても追いつく。次の回では退場が消える
- [ ] 罰 B で、本編の参加端末が全員退場したら、ホストはその時点で Result へ進む（回収額が目標額に届いていなければ失敗）
- [ ] 罰 B の退場した体験者の画面には「亡霊に見つかった… この回はここまで」を大きく出し、ビームを出さない。仲間の画面には「（色と記号）が亡霊に見つかった」を短く出す
- [ ] 本編の開始時（亡霊が初めて現れたとき）に、罰に合わせた一文を出す（A:「亡霊に見つかると、持っているお宝を奪われる。光の中に入らないで」 B:「亡霊に見つかると、その回はゲームオーバー。光の中に入らないで」）。文言は `ThTextTable` に置く
- [ ] 亡霊の体にお宝が当たっても減額しない（亡霊は当たり判定を持たない。視界の判定だけ）
- [ ] 運営PCの運営UIで、待機中に「亡霊: なし ／ お宝を奪う ／ 退場」を切り替えられ、`treasure_haul_settings.json` に保存される。回の途中では切り替えられない
- [ ] 体験の記録（CSV）の追加要素の欄に、亡霊の有無と罰の種類が残る。個人の記録に、見つかった回数（と罰 A で失った額）が残る
- [ ] コンパイルが通り、EditMode テストがすべて緑。PlayMode で、亡霊が経路を回り、視界に入った頭で罰 A・B が起きることを確認する（スクリーンショット）

## 制約
- 規約: UniTask / R3 / DOTween、ハンドトラッキング専用、.unity/.prefab/.asset は uloop 経由で編集
- 亡霊の位置は Playing の経過時間（`SessionClient` の残り秒）から決める。位置の RPC は足さない（RPC の上限 60回/秒を圧迫しない）
- 罰を決めるのはホスト（設計書 1章「進行の権限は運営PCのホスト」）。端末は「見つかった」を報告するだけ
- 罰 A の消滅・罰 B の解放は、既存の状態表の仕組み（世代 +1・`ThItems`・`ForceRestItemsOf`）に乗せる。独自の同期を作らない
- 純粋なロジック（経路・視界・見つかる判定・ホストの受け付け）は MonoBehaviour から分けて EditMode テストする
- 亡霊は物理の当たり判定を持たない（お宝・手と当たらない）。半透明は PICO の負荷を考えて、重ねる面を少なくする
- 外部の素材は使わない

## 検証方法
- EditModeテスト:
  - 経路: 経過 0 で出発位置、一周の長さ ÷ 速さの時間で元の位置に戻る、区間の途中の位置、向き
  - 視界: 距離・角度の内外、境界、真後ろ
  - 見つかる判定: 0.7秒続けて見つかる、途中で出たら数え直し、無視時間の間は見つからない
  - ホスト: 罰 A で持っているお宝が消滅・失った額の記録、何も持っていないと罰なし、Playing 以外・見学・退場・設定なし・無視時間内は捨てる。罰 B で退場・お宝の解放・つかむ申請を捨てる・次の回で消える・全員退場で Result
  - 設定: `ThPhantomMode` の読み書き、不正値で初期値。CSV の追加要素の欄
- PlayMode/目視:
  - 設定を「お宝を奪う」にして回を進め、Playing で亡霊が経路を回ることをスクリーンショットで確認
  - 体験者の頭（エディタのカメラ）を亡霊の視界へ動かし、0.7秒で見つかる・持っているお宝が消えることを確認。壁の裏では見つからないことを確認
  - 設定を「退場」にして同様に、退場の表示・つかめない・お宝がその場に置かれる・（1人参加なら）結果へ進むことを確認

## 実機確認が必要な項目
- PICO で、床の扇と半透明の亡霊がパススルーの明るい会場で見えるか、72fps を保てるか
- 曲がり角で出会い頭に見つかる感じが理不尽でないか（〔見つかるまでの時間〕の調整）
- 見つかりそうになって走る人が出ないか（安全）
