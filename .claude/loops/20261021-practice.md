Issue の本文と追記（コメント）: 追記に従い、**端末からの練習完了の申告（`ThTutorialDone`）は使わない**。練習用お宝もホストの状態表に入れ（番号は本編と重ならない）、Tutorial 中はホストが練習用お宝の `ThCollect` だけを受け付け、1回だけ受理して `ThCollected`（合計額は変えない）を全員へ送る。練習完了はホストが回収を確定した時点で記録する。Playing に入ったら練習用お宝をすべて消し、以後の練習用お宝のメッセージは捨てる。

## 目的
本編の前に、納品場所の目の前で「持つ → 値段がわかる → 運ぶ → 置いて回収」を1回ずつ成功させ、操作とゴールの場所を体で覚えてもらう。
- 練習用お宝は1人1つ。自分の色と記号（赤●・青▲・緑■・黄★）で見分けられ、自分のお宝の上に「あなたの」と出る。持てるのは自分のお宝だけ。
- 自分のビームも同じ色になり、仲間のアバターもその人の色になる（その回の結果まで続く）。誰が誰かがひと目でわかる。
- 10秒たっても持てない人には、手の横で手のモデルが「開く⇄握る」を繰り返して見せる。

## ユーザーと決めたこと（2026-10-21 の壁打ち）
- **回収地点の呼び方を「荷台」から「納品場所」に変える**。荷台（台車）は、お宝を運ぶための補助ツール（#46 のブランチ `repo/feature-th-asset-models` で `SalvageCart` を制作中。ゲームでの扱いは未確定）であり、ゴールではない。
  - オーケストレーターが、企画書・要件定義書・設計書・ナレーション原稿・TODO の回収地点の「荷台」「搬出リフト」を「納品場所」にそろえ、荷台（台車）は補助ツールだと書き足す。台車をゲームでどう使うかは未確定事項に足す。
  - 体験者に見せる文言もそろえる: 目的の一文 `GoalSentence`「宝を納品場所まで運ぼう。ぶつけると値段が下がる。みんなで目標額を目指そう」、オープニングの字幕 `OpeningLine3`「お宝を、納品場所まで運び出してくれ。」（U-5 は未決のまま。案を差し替えるだけ）。
  - コード・シーン上の名前（`CollectZone`・`Cargo`・`CargoBoardView`・`InCollectZone` 等）と仮の 3D は変えない。
- **練習の案内文**（頭について来る面に出す）:
  1. 持つ前: 「持ち手に手を向けて、握ろう」（既存 `PracticeGrip`）
  2. 持てた後: 「納品場所まで運ぼう」（新規 `PracticeCarry`）。持った瞬間の値札「150G」は今の値札の公開のまま
  3. 持っているお宝が納品場所の範囲に入ったら: 「納品場所の上で手を開こう」（新規 `PracticeRelease`）
  4. 回収の後: 「+150G！」（既存 `PracticeSuccessFormat`）を数秒大きく → その後、本編が始まるまで「ぶつけると値段が下がる」（既存 `PracticeDamageNote`。F-TUT-7）
  - 回収できなかった人は、本編で初めてぶつけたときの既存の一文で知る（今のまま）。
- **10秒のヒント**: プロジェクトにある XR Hands のサンプルの手のモデル（`Assets/Samples/XR Hands/1.7.3/HandVisualizer/Models/`）を手の横に大きく出し、「開く⇄握る」をコードで繰り返す。文字（既存 `GripBeam`「持ち手に手を向けて、ギュッと握ると持てる」）を添える。

## オーケストレーターが決めた実装の方針（設計書の範囲内の具体化）

### 色の割り当て（ホスト）
- Opening → Tutorial の時点の参加端末を、**端末番号の小さい順**に色番号 0〜3（`TutorialSlot` 0〜3 と同じ番号）へ割り当てる。端末番号（`treasure_haul_devices.json`）はまだ無いので、**今は DeviceId の文字列順**（`string.CompareOrdinal`）。並べ方は1か所の関数にまとめ、`// TODO(#44): 端末番号の順に差し替える` と書く。
- 割り当ては DeviceId → 色番号でホストが回の間持つ（新しい「開始」・Waiting で消す）。`ThState.tutorialColors` は `participants` と同じ順に色番号を入れる（割り当てのない端末は -1）。Tutorial → Playing で参加端末が減っても、残った端末の色は変えない。Playing・Result でも送り続ける（色はその回の結果まで続く）。
- 色の割り当ては運営UIから読めるようにする（`DeviceId → 色番号`。表示は作らない。#44 で使う）。

### 練習用お宝（ホスト）
- 番号は **`PracticeIndexBase = 100` ＋ 色番号**（100〜103。本編は 0〜22）。定数は1か所（例 `TreasureTypes` か `HostItemTable`）に置き、ホスト・端末・テストが同じ物を使う。
- `HostItemTable` は番号が連続しない表を扱えるようにする（`Get` を辞書などで引く）。今の本編の動きは変えない。
- Opening → Tutorial で、ホストは割り当てのある色ごとに練習用お宝を1つ作った状態表を持つ（種類 S、`Practice = true`、価値〔練習お宝の価値〕`practice.practiceValue`、置き位置＝その色の `TutorialSlot` の位置と向き、割り当てられた端末）。値段は公開していない状態から始める（持った瞬間に「150G」）。
- Tutorial 中に受け付けるのは、練習用お宝の `ThGrab`・`ThRelease`・`ThRest`・`ThCollect`・`ThPoses`（6.1 の条件＋「`ThGrab` は割り当てられた端末だけ」）。`ThDamage`・`ThLift` は捨てる（練習用は S だけ・減額しない）。
- **練習の回収**: 判定役の `ThCollect`、納品場所の範囲で止まった `ThRest`、範囲内に置かせた Placing の終わりのどれでも、Tutorial 中なら1回だけ回収済みにして世代 +1、`ThCollected`（`total` は本編の合計＝0 のまま、`value` = 練習お宝の価値）を全員へ送る。合計額は変えない。同時に、割り当てられた端末の練習完了の時刻を記録する（1回だけ。読めるようにするだけで、CSV・運営UIの表示は #44 と追加要素）。
- Tutorial 中は `ThItems` で練習用お宝の状態表を送る（取りこぼしから追いつく）。
- **Playing に入ったら**、練習用の表を捨てて本編の表を作る。以後、練習用の番号のメッセージは `Get` で見つからずに捨てられる。
- 結果・Waiting・中断の後片付けは今の本編と同じ。

### 端末
- `ClientRoundTracker` は `tutorialColors` から**自分の色番号**（無ければ -1）と、**DeviceId → 色番号**を読めるようにする（R3 の `ReactiveProperty` 等）。回が変わる・Waiting で消える。
- `SessionClientCore` は Tutorial に入ったら（回の途中から入って次の回を待つ端末と、`TutorialSlot` の無い環境では作らない）練習用お宝の `ClientItemTable` を作り、Playing で本編の表に差し替える（`TreasureClient` は表が替わると見た目を作り直すので、練習用お宝は全端末から消える）。
- `ClientItemTable` も番号が連続しない表を扱えるようにする。つかめる条件を「Playing 中の参加端末」から、**Tutorial 中は自分に割り当てられた練習用お宝だけ／Playing 中は今のまま**に広げる。練習用お宝は `ThDamage` を送らない（減額表示もしない）。
- 練習用お宝の見た目: カタログの `practicePrefab`（`TH_Practice`）を使い、`MaterialPropertyBlock` でその色の「練習用お宝の色」に塗る（共有マテリアルを書き換えない）。お宝の上に色の記号（●▲■★）、自分のお宝にはさらに「あなたの」（既存 `TagYours`）。値札は本編と同じく「？」→ 持った瞬間に「150G」。
- 自分のお宝の回収（`ThCollected` で自分の色の練習用番号）を受けたら、面に「+150G！」→「ぶつけると値段が下がる」（上の「練習の案内文」4）。

### プレーヤーの色（`ThPlayerPalette`）
- 新規 ScriptableObject `ThPlayerPalette`（`Settings/ThPlayerPalette.asset`。`ThContentSet` に `palette` を足す）。4枠それぞれ: 名前（赤・青・緑・黄）、記号（●▲■★）、ビームの色、アバターの色（ビームと同じ系統）、練習用お宝の色、アバターのテクスチャの差し替え（任意。空なら色だけ）。既定のビームの色・既定のアバターの色も持つ。`Validate()`（4枠ある、記号が空でなく重複しない）を足し、`ThContentSet.Validate` から呼ぶ。
- 初期値（見た目は R.E.P.O に似せない。後で調整してよい）: 赤 (1.0, 0.30, 0.30)・青 (0.30, 0.55, 1.0)・緑 (0.30, 0.85, 0.40)・黄 (1.0, 0.85, 0.20)。既定のビームの色は今のビームの見た目（`HandleAimed` のマテリアルの色）に合わせる。
- **ビーム**: 自分の色があれば、Tutorial〜Result の間、両手のビームをその色にする（`LineRenderer` の色か `MaterialPropertyBlock`）。待機中と色のない端末は既定の色。
- **仲間のアバター**: NetSync のアバター（`STYLY Default Avatar A 1`）はそのまま表示し、他の人のアバターの頭・手・体のメッシュを、その人の「アバターの色」で `MaterialPropertyBlock` で塗る。DeviceId → `GetClientNoByDeviceId` で今の ClientNo を引き、その ClientNo のアバターを探す（探し方は NetSync のコードを読んで決める。`OnAvatarConnected` と、ClientNo の入れ替わりに備えた定期的な確認で付け直す）。色のない人・待機中は塗りを外す。自分のアバター（`Avatar Local (Transparent)`）は塗らない。テクスチャの差し替えが設定されていれば同じく `MaterialPropertyBlock` で入れる。
- 体が頭について動くか（学習メモの「`BodyTransformSolver` の `netSyncAvatar` が空」問題）を `A 1` で確かめ、報告する（`A 1` のプレハブは `netSyncAvatar` が設定済みに見える）。動かなければ直さずに報告する。

### 会場（`TreasureHaulEnvironment.unity`）
- `VenueRoot` の下に `TutorialSlot` ×4 を置く（新規コンポーネント `ThTutorialSlot`。色番号 0〜3 を持ち、Gizmo に色と記号を出す）。納品場所（`CollectZone`）の前 1〜2m、納品場所の長い辺に沿って横一列（間隔は 0.6〜0.8m 程度）、床（y=0）に置き、納品場所の方を向ける。今の仮の会場の瓦礫・配置候補点と重ならない位置にする。
- `ThVenue` に `TutorialSlot` の一覧を足し、`CreateEnvironmentInfo` で `TutorialSlotCount` を入れる（パラメータの組み合わせ検査「`TutorialSlot` の数 ≧ 4」が動く）。`ThTreasureSetup` に練習の置き場所（色番号 → VenueRoot ローカルの位置・向き）を足す。
- シーンの変更は uloop 経由（YAML を直接書かない）。

### 頭について来る面（`ThPanelPresenter`・`ThPlayerPanel`）
- Tutorial の分岐を足す。練習用お宝が割り当てられている参加端末だけに、上の「練習の案内文」1〜4 を出す（割り当てのない端末・次の回を待つ端末は今のまま何も出さない）。判断（今どの段階か）は純粋クラスに置く: 入力は「自分の練習用お宝の状態（無い／置かれている／自分が持っている／持っていて納品場所の範囲内／回収済み）」と時刻。
- 「+150G！」は回収を知った時刻から数秒（コードの定数。例 2.5秒）大きく出し、その後「ぶつけると値段が下がる」に替える。

### 10秒のヒント（F-TUT-5）
- 練習用お宝が割り当てられている参加端末で、Tutorial に入ってから〔ヒントまで〕`practice.hintSeconds`（10秒）たっても、自分の練習用お宝を一度も持てていなければ出す。一度持てたら（承認を受けたら）消し、その回は出さない。Tutorial を出たら消す。保留中も出し続けてよい。
- 見た目: HandVisualizer の手のモデル（FBX をそのまま使う。改変しない）を、見えている手（右手を優先、見えなければ左手）の横 15cm ほど・1.5〜2倍の大きさで出し、指の関節の回転を DOTween で「開く⇄握る」を繰り返す（1往復 1.2秒程度）。少し下に `GripBeam` の文字。手を見失っている間は、頭の前やや下に出す。お宝・手の判定（`HandBone` レイヤー）・物理に影響しないこと（コライダーなし）。
- 判断（出す・消す）は純粋クラスに置いてテストする。
