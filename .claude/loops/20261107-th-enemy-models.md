## 目的

## 受け入れ基準

### A. 石像（角冠の王）— モデル
- [ ] 高さ **3.6m ±0.1m**（台座の底〜角の先）。人型の王が、角のある階段状の冠をかぶり、片手で杖を突き、もう片手を胸に当てて立つ。台座は階段状。
- [ ] 頭（冠・角を含む）が**別のメッシュ**で、原点が**首の回転の中心**にある。頭を Y 軸（Unity）で 0°・90°・180° に回しても、角・冠が胴・杖・肩にめり込まない（3枚の確認画像で示す）。首の継ぎ目は、胴側の襟で隠れる。
- [ ] 頭の**後ろ側も作り込む**（背を向けている時間が長い。後ろ髪の編み・冠の後ろの飾り板など）。
- [ ] 目が**別のメッシュ・別の材質**（`TH_StatueEye`）。普段は暗い石の目に見え、色・明るさを変えると光る（#68 がコードで変える。`_BaseColor` と `_EmissionColor` の両方を持つ材質）。
- [ ] 見た目: お宝・ステージと同じ文明の模様（衣の階段の帯、胸の同心円、波と歯の帯、冠の角）。角張った低ポリゴンに面取り、土と苔の汚れ、欠け・ひび。ステージの壁の石と並べて浮かない色味。遠くから見ても角の冠の輪郭でわかる。
- [ ] 描画の負荷: 三角形 **15,000 以下**（目を含む全体。1体だけ置くので、検収で 12,000 から緩めた）。材質は本体1つ（アトラス）＋目1つ。テクスチャは BaseColor（AO を焼き込み可）/ Roughness 等、1枚あたり最大 2048。透明は使わない。
- [ ] 当たり判定の形（床〜約2.1m を覆う箱を数個。台座・衣・腕と杖）を `stats.json` に書く（Unity の BoxCollider で作る。メッシュの当たり判定は使わない）。

### B. 亡霊（墓守の霊）— モデル
- [ ] 角のある頭巾（王の冠の角と同じ意匠を小さく）をかぶった墓守。顔は頭巾の奥の闇で、**目だけ**が光る。衣の胸に階段模様の帯。右手で竿を前に突き出し、竿の先に**吊り灯り**を下げる（灯りは体の前方 約0.6〜0.9m・高さ 約1.6〜1.9m）。
- [ ] 怖くしすぎない（一般客・子ども向け）。骸骨・血・歯をむき出す顔・ゆがんだ手は作らない。
- [ ] 浮いて滑る霊: 足は無く、**裾が下へ行くほど消える**（床から 約0.15m で完全に消え、約0.7m で不透明度が最大）。袖の先もぼかす（頂点色 A で不透明度を下げる）。
- [ ] 原点は床（裾の真下）。**目の中心の高さがちょうど 1.50m**（`ThPhantomParams.eyeHeight` の初期値。`PhantomView.Configure` が目の高さをこの値に置く）。正面は Unity の +Z。
- [ ] 部品を分ける: 体（頭巾・衣・袖・竿を1メッシュ。半透明）／顔の闇（不透明の暗い面）／目 L・R（`PhantomView` が色を変える）／灯りの光る芯（目と同じく色が変わる）／灯りの枠（暗い金属、不透明）。灯りは**揺らせるよう**、吊り点に原点を置いた別の階層にする。
- [ ] 描画の負荷: 三角形 **4,000 以下**。透明の面は体の1メッシュだけ（自分自身と重ならないよう、下記の深度の先行描画で1層にする）。

### C. Unity への組み込み
- [ ] FBX を `Assets/_Content/TreasureHaul/Models/Enemies/` に取り込む（1m＝1単位、正面 +Z、原点は床）。
- [ ] 新しいシェーダー `TH_PhantomGhost`（`Shader "TIB/TreasureHaul/PhantomGhost"`）: 光を受けない半透明。縁ほど明るい（フレネル）、裾で消える（オブジェクト空間の高さで、範囲は材質の値）、頂点色 A を掛ける、**目の前 0.6m より近いと薄くなる**（体がすり抜けたときに視界をふさがない）、裾がゆっくり揺れる（頂点を時間で少し動かす。下ほど大きく）。深度だけ書く先行パス→色のパス（ZTest LEqual）で、自分自身の重なりを1層にする。描画順は **3000**（Transparent。レビューで 2900 から変更: 2900 だと深度の先行パスが、後から描く値札・ビームを亡霊の陰で消すため。距離の並べ替えに任せる）。PICO のシングルパス・インスタンシングのステレオに対応する。
- [ ] 新しいシェーダー `TH_PhantomFan`（`Shader "TIB/TreasureHaul/PhantomFan"`）: 床の扇。左右の縁と先端の弧がやわらかく消え、弧の少し内側が明るい線、外へゆっくり流れる波紋。色は `_BaseColor`（不透明度を含む。`PhantomView` が MaterialPropertyBlock で塗る今の仕組みのまま）。描画順 2900 以下、ZWrite なし。灯りの光が床に落ちているように見える暖かみのない水色（警告中は今どおり赤）。
- [ ] `PhantomView.BuildFan` が UV（u = 角度 0〜1、v = 要からの距離 0〜1）を持つメッシュを作る。形（頂点の位置・三角形）は今と同じ。
- [ ] `TH_Phantom.prefab` を新しいモデルに差し替える。`PhantomView` の参照（BodyRoot・体・目・扇）を結線し直す。光る芯も「目」と同じく色が変わる（`_eyes` に含める）。灯りは吊り点で前後に小さく揺れる（DOTween。`PhantomView` に任意の参照 `_lanternPivot` を足し、無ければ揺らさない。表示・非表示を繰り返しても角度がずれない）。当たり判定は持たない（今どおり）。
- [ ] 新しいプレハブ `TH_Statue.prefab`: 本体・頭の回転軸（`HeadPivot`、首の位置）・頭・目 L/R・当たり判定の BoxCollider（`stats.json` の値。レイヤー・タグは、お宝が当たって減額される既存の障害物（ステージの瓦礫・壁）と同じにする）。シーンには置かない（置き場所と振り向く仕組みは #68）。

## 制約
- 規約: UniTask / R3 / DOTween、ハンドトラッキング専用、.unity/.prefab/.asset/.mat は uloop（エディタ API）経由で編集
- モデルは**外部素材を使わず** Blender のスクリプトで作る（有料素材・Blender MCP の生成機能・Sketchfab 等は使わない）。手続き的なテクスチャは画像に焼き込んで Unity へ持っていく。
- 版はフォルダやファイル名で分けず、1つの出力を上書きする（Git で履歴を持つ）。
- `.blend` は Blender 5.1 で保存。生成は `blender -b --factory-startup --python build_enemies.py`。ユーザーのライブ Blender は触らない。
- FBX の上書きは同じパスに（guid を保つ）。
- 透明は PICO の負荷に効くので、亡霊の体1メッシュ・扇1枚に限る。

## 検証方法
- モデル（Blender の確認画像。`Enemies/*/review/` に上書き）:
  - 石像: 正面・斜め・背面・頭のアップ、頭 0°/90°/180°、壁 2.4m と人 1.7m との比較、ステージの中（大広間の奥など）から見上げた画
  - 亡霊: 正面・斜め・横・背面、ステージの西の通路に置いた画（目の高さ 1.65m）、明るい背景（パススルーの会場を想定した明るい灰色）に置いた画、目と灯りが赤の画
  - 三角形の数・寸法・目の高さ・当たり判定の箱を `stats.json` と確認スクリプトで機械的に確かめる
- EditMode テスト:
  - `BuildFan` の UV（要は v=0、弧は v=1、u は左端 0〜右端 1）と頂点・三角形が今と同じ
  - オープニングの長さ（亡霊なし＝10秒、あり＝14秒）、字幕の番号（亡霊なしは 5 枚で今と同じ、ありは 0〜10秒で 1〜5、10〜14秒で 6）
  - 文言表に `OpeningLine6` と新しい文言がある・列挙の既存の番号が変わっていない
  - 既存の亡霊・セッションのテストが全部通る
- PlayMode/目視: `PhantomPlayDriver` で亡霊を巡回させ、Game ビューのスクリーンショットで、新しい体・目・灯り・扇が出ていること、見つかったときに目・灯り・扇が赤くなること、揺れ・灯りの揺れが動いていることを見る。`TH_Statue.prefab` をプレビュー（一時シーン）に置いて、頭の回転軸が首にあること・目の材質の色を変えると光ることを確かめる。

## 実機確認が必要な項目
- PICO の明るいパススルーの会場で、亡霊（半透明）と扇が見えるか。暗い壁の前と、会場が透けて見える所の両方
- 亡霊が出ている間も 72fps を保てるか（透明の重なり・扇）
- 体験者が亡霊をすり抜けたときに、視界がふさがれないか（近いと薄くなる）
- 石像の顔と角の冠が、壁越しに会場のどこから見えるか（置き場所は #68）
