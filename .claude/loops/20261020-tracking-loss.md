# 見失い・手の飛び・そっと置く・持ち主の切断

Issue: #41 ／ ブランチ: `repo/feature-tracking-loss`（`repo/develop` から作成）
設計書: `TREASURE_HAUL_DESIGN.md` 4.2・4.3・4.4・5章・6章（6.1・6.2）／要件定義書 F-GRAB-4・F-GRAB-6〜8・F-DMG-3・F-SCORE-1
Issue の本文: 見失い→Hovering→〔見失い待ち〕後に Placing（減額なし）。握ったまま戻れば持ち続け、手を開いて戻ったら Placing（U-14）／手の飛びの検出と〔補正の無判定時間〕／障害物で〔離れたら置く距離〕以上離れたら Placing／持ち主の切断で ThForceRest（荷台の範囲内ならホストが回収）。Issue に追記（コメント）はなし。

## 目的
手の認識が不安定でも、持っているお宝が勝手に落ちたり減額されたりしないようにする（企画書 2章の3「失敗の原因は、ぶつけたことだけ」）。
- 持っている手を見失ったら、お宝はその場で止まって待つ。握ったまま手が戻れば持ち続けられ、戻らなければ（または開いて戻れば）その場の床にそっと置かれる。
- 手の認識が一瞬飛んでも、お宝は振り回されず、戻る間は減額しない。
- 障害物に引っかかって手と大きく離れたら、その場にそっと置かれる。
- 持っている人の端末が切れたら、運営PCがその場にそっと置き、荷台の上なら回収する。

## ユーザーと決めたこと（2026-10-20 の壁打ち）
- **M を両手で持っていて両手とも見失ったとき**（片手が外れた後の〔M の猶予〕の間に、残った手も見失った場合を含む）は、**S と同じく〔見失い待ち〕**にする。その場で止めて 1.5秒待ち、**両手とも握ったまま戻れば**持ち続け、どちらかの手が開いて戻るか、時間切れならそっと置く。
  - オーケストレーターが企画書 5.2・要件 F-GRAB-4/6・設計書 4.2/4.3 に追記する（実装エージェントは文書を触らない）。

## オーケストレーターが決めた実装の方針（設計書の範囲内の具体化）
- **見失い待ち（Hovering）・そっと置く（Placing）は持ち主の端末だけの状態**。ホストの状態表は Held のまま（ホストへ新しいメッセージは送らない）。免除は今の `ThPoses` の `exempt` で知らせ、Hovering・Placing の間も位置を送り続ける（他の端末はそのまま補間して、止まる・降りる様子が見える）。そっと置き終わったら今の `ThRest` を送る（荷台の範囲内ならホストが今の `OnRest` で回収する）。
- **降ろす先の位置**は、新しい小さな部品（例: `ThPlaceSolver`。物理の Raycast を使うので純粋クラスにはしない）で決める: お宝の位置から真下へ Raycast し、当たった面の上に置く。対象は会場の物（床・荷台・瓦礫）だけで、`Treasure`・`TreasureHandle`・`HandBone` のレイヤー、トリガー、アバターのコライダーは除く。何にも当たらなければ VenueRoot の床（ローカル y=0）。向きは今の向きの Y 回転だけを残して立てる。お宝のプレハブは底が原点（配置候補点にそのまま置いている）なので、当たった点をそのまま位置にする。
- **持ち主の切断（`ThForceRest`）はホストが降ろす先を決める**（ホストも Environment を読み込んでいるので、同じ部品で Raycast できる）。ホストは「最後に受けた位置」（`ThPoses` から覚える。無ければ置き位置）から降ろす先を出し、`ThForceRest` に**降ろす先**を載せて送る。全員が今の表示位置からそこへ〔置く時間〕で降ろす。ホストは〔置く時間〕の後に「つかめる」に戻す（`ThFreed`）か、荷台の範囲内なら回収する（`ThCollected`）。端末どうしで降ろす先がずれない。
- **自分のお宝の免除は、`ThDamage` にも載せる**（`exemptA`）。位置の送信（1/30秒ごと）より先に衝突の報告が届くと、ホストが免除を知らずに減額してしまうため。相手のお宝の免除は今のまま、ホストが判断する。

## 受け入れ基準

### A. 握りの判定（Core: `GripStateMachine`・`HandGripTracker`）
- [ ] `GripStateMachine` に「握っている状態へ戻す」メソッド（例: `Resume()`）を足す。イベントは出さず `IsGripping = true` にする。以後、手を開けば今までどおり（〔離す判定〕の後に）`Released(Opened)`、見失えば `Released(Lost)` が出る
- [ ] `HandGripTracker` からも呼べるようにする（例: `ResumeGripping()`。`IsGripping` の `ReactiveProperty` も true にする）
- 理由: 見失い待ちから手が戻ったとき、「握りの強さが**離す側**のしきい値以上なら持ち続ける」（設計書 4.3）。新しい握りの確定（つかむ側のしきい値）を待たないので、握りの判定を握っている状態へ戻しておかないと、後で手を開いても離したことにならない

### B. 見失い待ち（Hovering。F-GRAB-6、設計書 4.3）— S
- [ ] S を持っている（承認済みで Held、または承認済みで手元へ飛ぶ途中）手の解除の理由が**見失い**なら、落とさずに **Hovering** にする: その場で止める（物理を止める。飛ぶ途中なら飛ぶのをやめてその位置で止める）。手（`HandGrabber.Held`）は外さない（ビームを出さず、別の物をつかまない）
  - 承認前（申請中）の見失いは今のまま取りやめ（元の位置へ戻す）
  - 手を開いた（理由=開いた）は今のまま落とす（Falling）
- [ ] Hovering の間に、その手が見える状態で戻ったとき:
  - 握りの強さが〔離す側のしきい値〕（`releaseThreshold`）以上 → **持ち続ける**（Held に戻り、手への追従を再開する）。握りの判定を握っている状態へ戻す（A）。〔補正の無判定時間〕を始める（E）
  - 握りの強さが離す側のしきい値未満（開いて戻った） → **Placing**（D）
- [ ] 〔見失い待ち〕（`lostWaitSeconds`、1.5秒）の間に戻らなければ **Placing**
- [ ] Hovering の間は減額の免除中（自分の `ThPoses` の `exempt = true`）。位置は送り続ける（止まった位置）

### C. 見失い待ち — M（両手で持った後）
- [ ] 両手で持っている M で、片手が外れたときの〔M の猶予〕は今のまま（残った手で持ち続ける。外れた手が握れば両手に戻る）
- [ ] 猶予の間に、**残った手も見失った** → **Hovering**（理由が「開いた」なら今のまま、すぐ落とす）。両手が同時に見えなくなった場合も、この順（1本目→猶予、2本目→Hovering）でここに来る
- [ ] M の Hovering の間に:
  - **両方の手**が見える状態で、両方とも握りの強さが離す側のしきい値以上 → 両手で持ち続ける（両手の中点・両手の線の向きの目標に戻す。猶予は消す）。両方の手の握りの判定を握っている状態へ戻す。〔補正の無判定時間〕を始める
  - どちらかの手が見える状態で、握りの強さが離す側のしきい値未満 → **Placing**
  - 片方だけ握って戻り、もう片方がまだ見えない → 待ち続ける
  - 〔見失い待ち〕の間に両手に戻らなければ **Placing**
  - M の Hovering の間は、両方の手の `HandGrabber.Held` をその M にしておく（ビームを出さない・別の物をつかまない）
- [ ] 猶予が切れたとき、外れた理由が**見失い**なら **Placing**（今は落としている。`TODO(#41)` を消す）。理由が「開いた」なら今のまま落とす
- [ ] 予約中（Locked）・持ち上げの申請中（`ThLifted` の前）の見失いは今のまま（予約は〔見失い待ち〕で解除、持ち上げの申請中は取りやめ）。今の `TODO(#41)` のコメントは、この扱いにした理由に書き換える（お宝は動いていない／飛ぶ途中の短い間なので元に戻すだけでよい）

### D. そっと置く（Placing。F-GRAB-6/7、設計書 4.2）— 持ち主の端末
- [ ] Placing に入ったら: 降ろす先（上の「方針」の Raycast）を決め、今の位置から降ろす先へ〔置く時間〕（`placeSeconds`、0.3秒）で、物理を止めたまま（kinematic で）動かす。向きは Y 回転だけ残して立てる
- [ ] Placing に入った時点で手から外す（S は持っていた手、M は両手の `Held`・両手の目標・猶予を消す）。手はすぐに別の物をつかめる
- [ ] Placing の間は減額の免除中（`exempt = true`）。位置は送り続ける
- [ ] 〔置く時間〕がたったら Resting にし、今の落下が止まったときと同じく `ThRest`（降ろした位置・向き。世代は今のまま）を送る（反映されるまで〔再送間隔〕で送り直す。今の仕組み）。荷台の範囲内に降りた場合も同じ（ホストの `OnRest` が回収する。F-SCORE-1）
- [ ] 減額しない（Placing のお宝は物理を止めているので自分では衝突を報告しない。他のお宝にぶつけられても、ホストが免除で捨てる）

### E. 手の飛びと〔補正の無判定時間〕（F-DMG-3、設計書 4.3）
- [ ] 手ごとに、手の目標（`HandGrabber.Anchor` に入れる位置）が、手が見え続けている間の1フレームで〔飛びの判定〕（`jumpDistance`、0.3m）以上動いたら「飛び」とする。そのフレームは目標を前の位置のまま止める。次のフレームからは新しい位置を使う（本当に手がそこへ動いたなら、追従の速度の上限で寄っていく。一瞬だけ飛んで戻った場合は、戻りも「飛び」になるので、お宝は動かない）
  - 判断は純粋クラス（例: `HandJumpFilter`。位置と「見えているか」を受けて、使う位置と「飛んだか」を返す）。手を見失ったら前の位置を忘れる（戻った最初のフレームは比べない）
- [ ] 飛びが、お宝を持っている（承認済みで Held の）手で起きたら、そのお宝の〔補正の無判定時間〕（`correctionGraceSeconds`、0.5秒）を始める。M は左右どちらの手の飛びでも始める
- [ ] 〔補正の無判定時間〕の間は: 減額の免除中（`exempt = true`）、「離れたら置く」（F）を判定しない。お宝は今の追従（障害物の手前で止まって滑る）で手へ戻る
- [ ] Hovering から持ち続けに戻ったとき（B・C）も、同じ〔補正の無判定時間〕を始める

### F. 離れたら置く（F-GRAB-7、設計書 4.3）
- [ ] 自分が持っている（承認済みで Held の追従中。M は猶予の間を含む）お宝の「手に合わせる点」と、手の目標（S は握っている手、M は両手の目標）との距離が〔離れたら置く距離〕（`detachDistance`、0.5m）以上になったら **Placing**（D）
- [ ] 手元へ飛ぶ途中・〔補正の無判定時間〕の間・Hovering・Placing では判定しない

### G. 減額の免除の報告（設計書 5章）
- [ ] `Treasure.IsDamageExempt`（または同じ役割の判定）: 手元へ飛ぶ途中・Hovering・Placing・〔補正の無判定時間〕の間なら true。位置の送信（`ThPoses` の `exempt`）はこれを使う（今のまま）
- [ ] 位置の送信の対象に Hovering・Placing を足す（今は Held・Flying・Falling だけ）
- [ ] `ThDamageMsg` の**末尾に** `exemptA`（bool。a のお宝＝送り手が動かしているお宝が免除中か）を足す
  - 端末: 自分のお宝が免除中に衝突したとき、相手が障害物（`b = -1`）なら送らない。相手がお宝なら `exemptA = true` で送る（相手の免除は今のまま、ホストが判断する）
  - ホスト: `exemptA` が true なら a には適用しない（b は今のまま判断する）。古い送り手からは false（JsonUtility の既定値）

  - 持ち主の切断はつなぎ合わせのテストで確かめる（エディタで端末を切るのは難しければ、そう報告する）
  - 確認が終わったら、起動したクローンのプロセスと Play を止める

## 制約
- 規約: UniTask / R3 / DOTween、ハンドトラッキング専用、`.unity` / `.prefab` / `.asset` は uloop 経由で編集（YAML を直接書かない）
- 判断は純粋クラスに置き、MonoBehaviour は配線と見た目だけ（設計書 1章）。時刻・手の状態（見えているか・握りの強さ）は引数で渡す（テストで時間を進められるように）
- 数値は `ThParams`（`lostWaitSeconds`・`placeSeconds`・`detachDistance`・`correctionGraceSeconds`・`jumpDistance`・`releaseThreshold`・`mGraceSeconds`）から取る。新しいパラメータは足さない
- 列挙・メッセージのフィールドは**末尾にだけ**足す。メッセージは今の形（`[0]` = RoundId、`[1]` = JSON）
- 世代の規則（設計書 4.2）を守る: +1 は持ち主を認めたとき・つかめるに戻したとき（`ThForceRest` の完了を含む）・回収・消滅、そして `ThForceRest` の送信時（持ち主を外すので、切れた端末の古いメッセージを世代で捨てるため）。端末の Hovering・Placing では世代を変えない
- 今の S・M の流れ（つかむ・置く・回収・減額・予約・猶予）を変えない。手を開いたときの挙動は今のまま
